# 智慧任務規劃

「AI 智慧任務規劃與管理系統」的前端設計規範。內容依照《資訊科技專題系統文件》第四章（功能需求）與第八章（介面規劃）整理：哪些畫面、每個畫面怎麼排、用什麼顏色和元件。

整體方向是**沉穩、簡潔、像一本規劃筆記本**：米白底、墨綠主色，只有和 AI 有關的地方會出現琥珀色。使用者每天會打開很多次，所以畫面要安靜、好掃讀，不要搶眼。

## 版面總覽

桌面優先，手機可用。

| 區域 | 尺寸 | 說明 |
| --- | --- | --- |
| 左側選單 | `sidebar-width` 240px | 系統名稱、首頁／我的目標／進度分析／設定，最下方固定「新增目標」 |
| 主內容區 | 最寬 `content-max` 1120px，左右留白 `space-6` | 超過就置中 |
| 表單欄 | `form-max` 640px | 新增目標、編輯任務 |
| 右側輔助欄 | 320px | AI 說明、AI 假設、篩選條件 |
| 手機（< 768px） | 單欄＋底部導覽 `bottom-nav-height` 64px | 側邊欄隱藏，新增目標變浮動按鈕 |

區塊之間一律用 `space-5`（24px），卡片之間用 `space-4`（16px）。

### 畫面清單與排法

「元件」頁的「版面 Layouts」群組裡，每一頁都有完整示意圖。

| 畫面 | 排法 | 對應需求 |
| --- | --- | --- |
| 首頁／儀表板 | 4 張統計卡 → 左 7：近期任務｜右 5：完成率環形圖＋AI 今日建議 | PROG-01～05、ADV-01 |
| 新增目標 | 左：表單｜右：AI 會做什麼＋範例 | GOAL-01、AI-01 |
| AI 任務預覽 | 左：可直接編輯的草稿表格｜右：AI 的理解與假設；底部固定「確認並儲存 N 個任務」 | AI-02～05 |
| 目標詳情 | 目標資訊卡（含進度條）→ 狀態分頁＋篩選工具列 → 任務清單 | GOAL-02、TASK-01～06 |
| 進度分析 | 篩選（目標、期間）→ 統計卡 → 環形圖 5｜長條圖 7 → 需要注意的任務 | PROG-01～06、ADV-02 |
| 設定（可選） | 單欄表單，分「個人資料」「通知」兩區 | USR-02、PLAN-06 |

### 使用者動線

首頁按「新增目標」→ 填表 → AI 草稿（可改、可重來）→ 確認儲存 → 自動進入目標詳情 → 勾選完成 → 首頁和進度分析的數字跟著更新。

AI 掛掉時，新增目標頁和草稿頁都有「手動新增」可以走，不會卡住。

## 顏色

| 用途 | Token | 規則 |
| --- | --- | --- |
| 頁面底 | `bg` | 米白，不用純白，長時間看比較不刺眼 |
| 卡片 | `surface` + `line` 外框 | 靠外框分區，陰影只有很淡的 `shadow-card` |
| 主要動作 | `primary` | 一個畫面只有一個主要按鈕 |
| AI | `accent`、`accent-ink`、`accent-soft` | **只給 AI 用**：AI 按鈕的小圓點、AI 草稿標籤、AI 建議卡底色。看到琥珀色就知道「這是 AI 產生的、還沒確定」 |
| 任務狀態 | `status-todo` / `status-doing` / `status-done` / `status-overdue` 各有一個 `-soft` 底色 | 只用在狀態標籤和圖表 |

所有文字和底色的對比都至少 4.5:1（淺色、深色模式都有檢查）。`ink-faint` 例外，只能用在 placeholder 和停用狀態。

## 狀態與優先級

這兩個最容易搞混，所以刻意用不同的視覺方式：

- **狀態**用顏色＋文字：待辦（灰）、進行中（藍）、已完成（綠）、逾期（紅）。逾期由系統判斷，不能手動選。
- **優先級**用深淺：高＝實心深色、中＝外框、低＝淡灰。不用紅黃綠，避免和「逾期」的紅色搶，色弱也分得出來。

## 字體

中文用 Noto Sans TC（使用者電腦沒有時，Mac 會用蘋方、Windows 用微軟正黑體）；統計數字用 Inter，數字比較整齊。

| 字級 | 用在 |
| --- | --- |
| `display` 32px | 首頁問候語 |
| `h1` 24px | 頁面標題，一頁一個 |
| `h2` 18px | 卡片標題 |
| `body` 15px | 任務名稱、一般文字 |
| `body-sm` 13px | 日期、工時、說明 |
| `stat` 28px | 統計卡數字 |

## 圓角與間距

按鈕、輸入框、任務列用 `radius-md`（10px）；卡片用 `radius-lg`（14px）；標籤、進度條用 `radius-pill`。間距以 4px 為單位：`space-1` 4 → `space-7` 48。

## 文字怎麼寫

- 按鈕用動詞：「AI 幫我拆解」「確認並儲存 8 個任務」，不要只寫「確定」「送出」。
- AI 產生的內容一律叫「草稿」或「建議」，旁邊標「僅供參考」。
- 錯誤訊息講發生什麼事、可以怎麼做：「AI 這次沒有回應。你可以再試一次，或先手動新增任務。」
- 日期用「今天」「明天」「已逾期 1 天」這類說法，超過一週才寫日期。

## 元件

| 元件 | 用途 |
| --- | --- |
| Button | 主要／一般／文字／危險按鈕；AI 按鈕前加琥珀小圓點 |
| StatusChip | 任務狀態標籤＋AI 草稿標籤 |
| PriorityBadge | 高／中／低 |
| FormField | 表單欄位、提示與錯誤 |
| Feedback | 錯誤框、成功框、Toast |
| StatCard | 統計卡片 |
| TaskItem | 任務列 |
| ProgressBar | 目標進度條 |

樣式都寫在 `components/bundle.css`，class 以 `tp-` 開頭（例如 `tp-btn tp-btn--primary`、`tp-chip tp-chip--overdue`），可以直接搬到 HTML／React 專案使用。圖表顏色用 `c-done`、`s-doing` 這類 class 綁到 token。
